# L5: Verification

The criteria and checks used to decide whether work is correct. Compare tests, evaluation methods and whether a failed check actually blocks progress.

## Primary tools

| Tool | Purpose | Artifact | Verification |
|---|---|---|---|
| [Opik](../../data/tools/comet-ml__opik.json) | Tracing, evaluation and prompt management for LLM applications, self-hostable in full rather than as a cut-down edition. | traces, evaluation runs and prompt versions (persistent) | ok |
| [DeepEval](../../data/tools/confident-ai__deepeval.json) | Writes LLM output evaluation as unit tests, in pytest-compatible form. | test code (persistent) | ok |
| [Coze Loop](../../data/tools/coze-dev__coze-loop.json) | A self-hostable platform for developing and operating agents: prompt management, evaluation and monitoring in one deployment. The open edition is the core of a commercial product. | prompts, evaluation sets and traces held in a deployed service (persistent) | ok |
| [hol-guard](../../data/tools/hashgraph-online__hol-guard.json) | Local-first runtime security layer that intercepts AI-agent tool calls, package/plugin installs and MCP traffic across 13+ CLI harnesses, blocking or requiring human approval before risky actions execute. | local approval/receipt history and policy state (persistent, ~/.hol-guard-style local store); plugin-scanner separately emits SARIF/verification payloads for CI | ok |
| [judgeval](../../data/tools/judgmentlabs__judgeval.json) | Traces an agent with OpenTelemetry and scores its behaviour with prompt-defined judges, so a failure can be traced to a cause and a fix validated against the case that produced it. | traces and scored behaviours (persistent) | ok |
| [Langfuse](../../data/tools/langfuse__langfuse.json) | Tracing and evaluation substrate. Records every LLM call and its cost so runs can be reconstructed. | traces and eval definitions (persistent) | ok |
| [TDD Guard](../../data/tools/nizos__tdd-guard.json) | Blocks implementation written before a test, via hooks. Turns TDD from discipline into enforcement. | hook configuration (persistent) | ok |
| [SkillSpector](../../data/tools/nvidia__skillspector.json) | Scans an agent skill before it is installed, looking for prompt injection, exfiltration paths, malicious patterns and supply-chain risk, and reports whether it is safe to install. | scan reports (persistent) | ok |
| [promptfoo](../../data/tools/promptfoo__promptfoo.json) | Codifies prompt and agent evaluation and runs it in CI. Also does red-teaming. | eval definitions (persistent) | ok |
| [Semgrep OSS](../../data/tools/semgrep__semgrep.json) | Rule-based static analysis. Functions as a deterministic gate on generated code. | rules (persistent) | ok |
| [Inspect AI](../../data/tools/ukgovernmentbeis__inspect_ai.json) | Evaluation framework from the UK AI Safety Institute. Leans on reproducibility and rigorous logging. | evaluation task definitions (persistent) | ok |
| [Strix](../../data/tools/usestrix__strix.json) | A penetration testing agent for an application you own. It reads the source, runs the application in a Docker sandbox, and reports only the weaknesses it could reproduce with a working proof-of-concept exploit. Nine skills let Claude Code, Cursor or Codex start a scan, fix the findings and set up scanning on pull requests. | one Markdown file per finding plus vulnerabilities.json, under strix_runs/<run-name>/ (persistent) | ok |
