# L1: Environment and tools

Execution boundaries, tool access and the environment in which an agent can act. Compare sandbox, approval and network controls with the tools the task requires.

## Primary tools

| Tool | Purpose | Artifact | Verification |
|---|---|---|---|
| [agent-lsp](../../data/tools/blackwell-systems__agent-lsp.json) | MCP server that orchestrates existing LSP servers (gopls, rust-analyzer, and 29 more) into batched, speculative and phase-enforced workflows for AI coding agents. | warm MCP/LSP daemon process (ephemeral); auto-exits after 30 minutes idle, no artifact survives removal | ok |
| [Browser Use](../../data/tools/browser-use__browser-use.json) | Gives an agent a browser it can actually use: pages, clicks, forms and extraction, driven from a task written in words. | browser sessions and extracted data (ephemeral) | ok |
| [gh-aw](../../data/tools/github__gh-aw.json) | GitHub's official CLI extension compiling Markdown+YAML agentic workflows into sandboxed, permission-scoped GitHub Actions runs across five built-in AI engines. | compiled .lock.yml GitHub Actions workflow committed to the repo (persistent) | ok |
| [Strands Agents](../../data/tools/strands-agents__harness-sdk.json) | An SDK for the loop you would otherwise write yourself: turn limits, token budgets, cancellation and stop reasons as first-class controls, running in your own process with no hosted control plane. | agent definitions in Python or TypeScript (persistent) | ok |
